# IMPLEMENTATION SPEC

## 1. Objective

Reduce the remaining Ruff backlog from 149 errors to zero without changing integration behavior. The work covers the current categories reported by `scripts/lint-check`: 92 `ANN401`, 37 `E501`, 15 `C901`, 3 `SIM102`, 1 `ANN202`, and 1 `UP035`. Definition of done: `scripts/lint-check` passes cleanly, targeted tests still pass for the touched subsystems, and no new dependencies, compatibility shims, or behavior changes are introduced.

## 2. Scope

- In scope:
  - Replace `Any` in signatures where a simpler concrete type, `object`, `Protocol`, `Callable`, or existing Pydantic AI / Home Assistant type is already implied by the code.
  - Refactor high-complexity functions into smaller private helpers without changing runtime behavior.
  - Wrap long imports, prompt strings, error messages, and serialized test payload setup to satisfy `E501`.
  - Resolve the remaining `SIM102`, `ANN202`, and `UP035` findings.
  - Update affected tests only when type-driven refactors require fixture or helper alignment.
- Out of scope:
  - New features, behavior changes, provider logic changes, config-flow UX changes, or schema changes.
  - Dependency changes, repo-wide formatting policy changes, lint-rule suppression, or relaxing Ruff configuration.
  - Broad type-system redesign beyond what is needed to satisfy the existing errors.
- Assumptions implementers must not expand beyond:
  - Prefer the smallest local fix.
  - Keep public behavior, event payloads, prompts, and streamed adapter semantics unchanged.
  - Do not add new permanent documentation files or new dependencies.

## 4. Constraints

- Language and framework constraints:
  - Python 3.14 repo conventions apply. Use lazy annotations and modern typing where it simplifies code.
  - Follow Home Assistant custom-integration patterns and existing Pydantic AI public APIs only.
- Style constraints:
  - Prefer `object` plus local `isinstance` checks over `Any` when the function already narrows at runtime.
  - Prefer existing concrete types from HA or Pydantic AI over new custom abstractions.
  - Use `Protocol` only where a private concrete type import would be unstable or where tests rely on duck typing.
  - Refactors for `C901` must be extraction-based. Do not rewrite behavior or reorder semantics unless required to preserve exact outputs.
  - Keep long-string fixes behavior-neutral: adjacent literals, wrapped f-strings, helper builders for test SSE chunks, and wrapped imports.
- Safety and compatibility constraints:
  - Do not change provider request payload semantics, finish-reason mapping, streamed event ordering, diagnostics payload shape, or todo-workspace rule text content.
  - Do not import private third-party types just to satisfy lint when a small `Protocol` or `object` is enough.
  - Do not suppress lint rules with `noqa` unless an exact type cannot be expressed cleanly after trying the simpler local options first.
- Dependency constraints:
  - No new dependencies allowed.

## 5. Implementation steps

1. Clear the single-rule leftovers first: replace `typing.AbstractSet` with `collections.abc.Set` in `model_settings.py`, add the missing contextmanager return annotation in `openai_compatible_adapter/_chat_model.py`, and fix the three `SIM102` nested-condition sites in `config_flows/common.py`, `config_flows/provider_flow.py`, and `openai_compatible_client/_streaming.py`.

2. Resolve the low-risk `ANN401` cases by replacing `Any` with `object`, existing HA types, or existing Pydantic AI types where the runtime contract is already obvious. Default choices: `object` for `__init__.py`, `_redaction.py`, and `run_diagnostics.py` narrowing helpers; `HomeAssistant` and `ConfigSubentry` for HA-owned objects; `Model` for provider/model-construction helpers; `OutputObjectDefinition` and existing message/content types for adapter mapping helpers.

3. Introduce the smallest shared typing helpers needed for the remaining `ANN401` cases. Default choices: a narrow `Protocol` for objects with `set_attributes(...)` instead of importing a private Logfire span type; a usage-like `Protocol` or existing `pydantic_ai.usage` type that still matches the test doubles in `tests/components/pydantic_ai_agent/support/pydantic_ai.py`; `Callable[..., object]` or similar for serializer/tool callbacks; and `RunDiagnosticsRecorder | None` for `ha_toolset.py`.

4. Refactor the streaming and runtime complexity hotspots with extraction-only helpers, starting with the largest risk areas: `chat_deltas._agent_events_to_chat_deltas`, `openai_compatible_adapter/_responses_streamed_response.py::_get_event_iterator`, `provider_validation.async_probe_model`, and `config_flows/common._parse_model_settings`. Preserve branch order and emitted data exactly. Recommended default: extract per-branch helper functions and keep the main loop or dispatcher flat.

5. Refactor the remaining `C901` functions in dependency order: `chat_deltas._agent_messages_to_chat_deltas`, `__init__._configured_subentry_models`, `ai_task._async_generate_data`, `openai_compatible_adapter/_streamed_response.py::_get_event_iterator`, `config_flows/common._normalise_provider_model_profiles`, `config_flows/common._normalise_run_settings`, `config_flows/provider_flow._sync_selected_model_profiles`, `provider.list_google_gemini_model_names`, `run_failures._classify_run_failure`, and `virtual_workspace.patch._parse_patch`. Keep each extraction local and private.

6. Fix the source-file `E501` issues with behavior-neutral wrapping only. Use adjacent string literals for prompt text and error messages in `skills.py`, `virtual_workspace/__init__.py`, `ha_todo_tools.py`, `model_request_settings.py`, adapter mapping files, and `provider_validation.py`. Use wrapped parenthesized imports for the provider-wizard test modules.

7. Replace the raw serialized SSE test strings with small local helper builders in `tests/components/pydantic_ai_agent/test_openai_compatible_adapter.py` and `test_openai_compatible_client.py`. Recommended default: helper functions that build one `data: ...\n\n` chunk for text, reasoning, tool-call, and usage events, so the tests keep readable intent while eliminating the longest literals.

8. Align any impacted tests and support helpers with the new typing contracts, then run focused validation before broad validation. Update only the minimum fixtures or helper classes needed to satisfy the new annotations and extracted helpers.
